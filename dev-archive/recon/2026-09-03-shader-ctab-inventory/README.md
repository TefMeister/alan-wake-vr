# Shader CTAB inventory — Alan Wake, 2026-09-03

Generated by `/pd` on the dev PC, **with the game not running**. Static read of
`<install>\shaders\build\pc\*.obj` (62 `RFX ` containers, ~16 MB) using
`flat-to-vr-RE-toolkit/tools/d3d9-ctab.py`.

**No game content is stored here.** These are constant *names*, register indices and counts —
interface metadata we generated, the same category as an export-name dump. The shader bytecode
itself stays in the install folder.

## Files

| file | what it holds |
| --- | --- |
| `transform-constants.txt` | every constant whose name mentions clip/view/proj/camera/eye/world/near/far/fov — 33 names, with the register each lands on per stage |
| `register-map-and-skinning-correlation.txt` | the camera/projection register map, plus the per-shader test of "skinning palette pushes the camera block to c192" |
| `clip-matrix-coverage.txt` | how many vertex shaders carry a `*ToClip` matrix, and what the ones that do not are |
| `aw_names.py`, `aw_agg.py`, `aw_cov.py` | the three scripts that produced the above, so the numbers can be reproduced or re-run against a patched build |

## Reproducing

The scripts import `d3d9-ctab.py` by absolute path from the toolkit clone and read the install
folder by absolute path. Both paths are at the top of each script — edit them for another machine
(see `claude-memory/MACHINES.md`), then:

```bash
python aw_names.py
python aw_agg.py
python aw_cov.py
```

## Headline numbers

- 9,971 constant tables, 691 distinct layouts.
- `g_mViewToClip` (`vs_3_0`, 4x4) = the standalone projection matrix, in 4,467 shaders.
- `g_mLocalToView` (`vs_3_0`, 4x3) = object-to-view, in 4,553 shaders.
- The projection register is **not fixed**: `c0` (2,238), `c192` (2,084), `c4` (128), `c7` (17).
- 97.6% of vertex shaders carry some `*ToClip` matrix; the 121 that do not are post-process.
